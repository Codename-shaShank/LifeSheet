# LifeSheet — project memory

Personal DSA prep tracker, similar to Striver's A2Z sheet. Built by Shashank for his own
interview prep, shared with at most 5 people. Problems come from his spreadsheet
(LIFE_SHEET.xlsx); most links go to LeetCode.

## Working rules

- **Ask before executing anything** (installs, scripts, builds, git, deletes). Reading files is fine.
- Stay within MERN: React (Vite, JavaScript) + Express + MongoDB. No other backends or services.
- Keep the backend small. No extra middleware layers, queues, caches or microservices.
- Everything is **mapping-driven**: new collections, sheets, problems, notes fields or nav items
  are added by editing JSON/config, never by hard-coding them in components.
- Problems are **never hard-coded**. They come only from the spreadsheet via `npm run ingest`.
- Unbuilt features are marked with `// FUTURE:` comments at the place they'll live. Keep adding them.
- The UI is dark-only and must match the reference screenshots (tokens in `client/src/styles/global.css`).

## Architecture: content vs. user data

| Content — JSON in `client/src/content/` | User data — MongoDB |
|---|---|
| collections, sections, sheet cards, modules, groups, problems, links, solutions | account, done/saved flags, notes |
| edited by hand or generated by the ingest script | written by the app via the API |

They are joined only by the problem `id`: the LeetCode slug when the link is LeetCode
(stable across renames), otherwise `<module>-<slug(title)>`. The server never stores titles
or links. All counts, percentages and "Up next" are computed on the client
(`client/src/lib/sheetTree.js`), so the server only stores flags per problem.

## Spreadsheet → content mapping (ingest)

- Each workbook tab = one module. `ALL PROBLEMS SHEET(LONG TERM)` is skipped (notes-format tab).
- Rows like `ARRAYS : MEDIUM`, or a single-cell row directly above a `QUESTION LINK` header,
  start a group. Header rows set column positions. Every other row with column-A text is a problem.
- Column A hyperlink → `links[0]` with a detected platform. SQ1–SQ3 → `similar[]`
  (bare numbers become LeetCode search links; "premium" is dropped; free text kept as a label).
- Personal columns (DIFFICULTY, TAKEAWAYS, APPROACH, TC, SC…) are ignored on purpose.
- Only whole-cell hyperlinks survive a Google Sheets → xlsx export.
- Misdetections are fixed in `ingest.config.mjs` (`forceGroupTitles`, `forceProblems`,
  `groupTitleOverrides` with `#2` for a second occurrence).

## MongoDB (Atlas M0 free)

- `users`: name, username (unique, lowercase), email (unique), passwordHash (bcrypt, select:false),
  role user|admin.
- `userproblems`: userId, problemId, done, completedAt, saved, notes (free-form object),
  hasNotes. Unique index `{userId, problemId}`. No row = untouched problem.
- No schema needs creating in Atlas; Mongoose creates collections and indexes on first start.

## API (all JSON, session in httpOnly cookie `ls_session`, 7 days)

```
POST /api/auth/signup  {name, username, email, password, inviteCode}  (invite + MAX_USERS cap)
POST /api/auth/login   {identifier, password}      identifier = email or username
POST /api/auth/logout
GET  /api/auth/me      → {user} or {user:null}
GET  /api/progress     → [{problemId, done, saved, hasNotes, difficulty}]   one call per session
PATCH /api/progress/:problemId  {done?, saved?}    upsert
GET  /api/notes/:problemId      → {notes}
PUT  /api/notes/:problemId      {notes}             replaces; empty fields dropped
GET  /api/admin/users           admin only
GET  /api/health
```

Notes keys are not fixed on the server (regex-validated), so adding a field in
`notesSchema.js` needs no backend change. The ADMIN_EMAIL account gets the admin role at signup.

## UI spec (match the screenshots)

- **Shell:** floating dark panels on a darker gutter. Sidebar (collapsible) | top bar (search icon,
  flame streak "0") over main. Daily Planner card on the right of main, hidden on the problem page.
- **Sidebar:** Prep section → Dashboard (= profile for now), Prep Hub, Practice (submenu chevron,
  coming soon), Community (coming soon). My Spaces section → Completed. User chip at the bottom
  opens a menu: Profile, Notifications, Account ›, Troubleshooting, Theme switch (inert), Logout.
- **Prep Hub (home):** tabs DSA / Core CS / System Design / Data Engineering; only DSA clickable.
  DSA has one section "Learn From Zero" with one card "Sequence DSA Sheet": Modules and Topics
  counted from the sheet, Contests and Hrs from dsa.json, Explore → listing page.
- **Listing page:** breadcrumb, title + description, "Up next: <first undone>" button (expands its
  module/group and scrolls to it), Overall Progress card (% and done/total, medal at 80 %),
  toolbar (search, filter, gauge, shuffle, more — inert for now), then the accordion:
  module (mini bar + done/total) → group (same) → problem rows.
- **Problem row, left to right:** checkbox (green when done) · title · difficulty pill if set ·
  1 Solution (→ problem page) · 2 Platform link (new tab) · 3 Notes (modal) ·
  4 Save (bookmark, persisted) · 5 three dots (clickable, does nothing yet).
- **Notes fields, in this order:** Difficulty (Easy/Medium/Hard — difficulty is entered by the user
  here, not from the sheet), Pattern, Takeaways, Approach, Time complexity, Space complexity,
  Pitfall, Revision.
- **Problem page:** statement + solution from `content/solutions/<id>.json` (placeholders otherwise),
  similar problems as chips, and a right-hand AI chat panel that is disabled for now.
- **My Spaces → Completed:** done problems in the same module/group tree, no progress bars.

## Deployment

Backend on Render (root `server`, start `npm start`, env from `.env.example` with
`NODE_ENV=production`, `TRUST_PROXY=2`). Frontend on Vercel (root `client`); replace
`YOUR-RENDER-SERVICE` in `client/vercel.json`. The /api proxy keeps the cookie first-party.
